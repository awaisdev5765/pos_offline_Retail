What this software does

This is a Point of Sale (POS) system for retail-style businesses. It records sales, keeps inventory (stock), manages customers (including credit / Khata), suppliers, expenses, banks, and can print or preview receipts. It is designed to run offline so the shop keeps working without internet.

Internet is optional — mainly for online backup (getting a download link) or any network features your seller enabled.

Before you start

  • Use a reliable Windows PC for production use.
  • Set correct date, time, and time zone — monthly license activation depends on the calendar month.
  • Prepare: business name, address, phone, default currency, and approximate tax rate (if you charge tax).
  • Keep monthly license codes private and backed up (printed or in a password manager).

Installation and first launch

  1. Install from the file or instructions your seller provided (for example a Windows executable).
  2. Launch the app. You may see a splash screen while the database prepares.
  3. If Business setup appears, complete it (name, logo, tax, currency, etc.).
  4. If License activation appears, enter the current month’s 16-character code.
  5. If Login appears, sign in with the admin or staff user your seller configured.
  6. You should reach the Dashboard (home) with shortcuts or a sidebar to other screens.
First day habit: After setup, go to Settings → Data Management → Create Backup once. That gives you a clean “starting point” file if anything goes wrong later.

License (monthly activation)

Each calendar month has its own 16-character code (letters and numbers, no spaces). The code for April only works when the computer’s date is in April.

  1. Open Settings from the main menu or sidebar.
  2. Open License Management (or follow any on-screen “activate license” prompt).
  3. Type the code exactly, then confirm. You should see that the license is active until the end of that month.
  4. On the first day of a new month, repeat with the new month’s code.
Treat codes like passwords. Do not post them on social media or send in unsecured group chats.

Business setup and Settings

Most shop-wide options live under Settings:

  • Business name, address, phone — usually printed on receipts.
  • Tax rate — used when the POS calculates tax on the bill (if your workflow uses it).
  • Currency — symbol and formatting on screens and reports.
  • Dark mode, language, receipt options, printers — adjust as needed.

After changing settings, look for Save (or equivalent) so values are written to the database.

Main screen and menu

The Dashboard is your home page. From here you typically open:

  • POS — the selling screen (the “till”).
  • Products — list, search, add, and edit items you sell.
  • Categories — group products (required before or while adding products).
  • Customers — people you sell to on credit (Khata) or for records.
  • Sales — history of past bills.
  • Reports — summaries and detailed reports.
  • Settings — business profile, license, backups, and more.

Exact layout depends on version (sidebar, tiles, or top menu), but the names above are what you should look for.

Categories — full guide

Every product must belong to a category (for example “Drinks”, “Groceries”, “Phone accessories”). Categories keep the POS organized and speed up searching.

Opening Categories

  1. From the Dashboard or menu, tap Categories.
  2. You will see a list of existing category names (may be empty on a new install).

Adding a category

  1. Tap Add Category (or similar).
  2. Enter a clear name customers and staff will understand.
  3. Save. Repeat until you have the main groups you need (you can add more later).

Renaming or cleaning up

Use your app’s edit/delete actions on the category list if you made a typo. If the app prevents deleting a category that is still used by products, move those products to another category first (edit each product’s category).

Recommended order: Create categories before mass-adding products, so every new product can pick a category from the dropdown immediately.

Products — full guide

Products are the items (or services) that appear on the POS. This section walks through the real screens: Basic Information, Inventory, Additional Information (pricing), and optional blocks for special business types.

Opening the product list

  1. From the menu, open Products.
  2. Use the search box to find by name or barcode.
  3. Tap a row to view or edit (depending on permissions).
  4. Look for Add Product (or a “+” button) to create something new.

Creating a new product — step by step

  1. Open Products → Add Product.
  2. Work from top to bottom in the form so you do not miss required fields.
  3. In Basic Information, fill Product Name (required) and Category (required):
    • Choose an existing category from the dropdown, or pick Add New Category, type the new name, then continue.
  4. Barcode (optional): type the code, or tap the camera / scanner icon if your device has a camera scanner — point at the barcode until it fills in.
  5. In Inventory:
    • Current Stock — for a new item in retail mode, you can often enter 0 if you will receive stock later through Purchase / stock movements; the form may show a hint that ongoing stock is updated by purchases. If you already have physical stock on the shelf, enter the real quantity.
    • Unit — choose how you count the item (for example pcs, kg, box). This appears on labels and reports.
    • Reorder Level — when stock falls to this amount (or below), you know it is time to restock.
    • Reorder Qty — how many you typically order when restocking.
  6. In Additional Information → Product Pricing (names may vary slightly):
    • Retail Cash — the normal selling price when the customer pays cash (required in standard retail layout).
    • Cost Price — what you paid for the item (your cost). The screen usually shows profit and margin when price and cost are both filled.
    • Retail Credit — price when selling on customer credit (Khata), if different from cash.
    • Wholesale Cash / Wholesale Credit — lower tiers for bulk buyers, if you use wholesale mode on the POS.
    • Market Price — optional reference (e.g. MRP on packaging).
  7. Scroll through any remaining sections: tax, discount, description, packing mode, etc. Fill only what your shop uses.
  8. Tap Save (or “Add product”). Wait for the green success message.
  9. Return to Products list and confirm the new row appears. Optionally open POS and search for the product to test a sale.

What each main field means

Product NameThe label staff and you see on the POS. Use unique, clear names. CategoryGroups the item for browsing and reports. BarcodeLets you scan the item at the till instead of searching by name. Current StockHow many units you have now. Updates when you sell and when you receive stock (depending on your workflows). Unitpcs, kg, liter, etc. Reorder Level / QtyLow-stock warning and typical order size. Retail CashDefault customer price for cash sales. Cost PriceYour purchase cost — for profit calculation. Retail CreditPrice tier when posting to customer Khata. Wholesale fieldsUsed when POS is in wholesale mode for bulk buyers.

Editing an existing product

  1. Open Products, find the item, open it for edit.
  2. If you see Read-only mode with a switch for Editing mode, turn Editing mode on before changing fields (this protects accidental edits).
  3. Change prices, description, barcode, or reorder levels as needed.
  4. Stock on hand: For existing products in retail setups, stock is often updated by purchases and sales, not by typing a random number. If you do a physical stock count, use proper stock adjustment or inventory tools your app provides so history stays correct.
  5. Save and confirm the list shows updated values.

Bundles, ingredients, mobile shop

  • Bundles / combo — if your version has a Bundles screen, you can sell a package of multiple products as one line. Configure bundles there, not only inside a single product.
  • Restaurant / ingredients — for menu items made from raw materials, the product form may let you attach ingredients and quantities so costs and stock can follow recipes (when that mode is enabled).
  • Mobile shop fields — brand, model, IMEI, warranty, etc., appear when your business profile is set up for phone shops; fill them for warranty and serial tracking.
  • Bulk import — from Products, if your seller enabled Excel/CSV import, you can import many rows at once; column names must match the template your seller provides.

Using the POS (selling at the till)

The POS screen is where you build a bill, take payment, and finish the sale. Learn this screen well — it is used all day.

Building the cart

  1. Open POS from the menu or dashboard.
  2. Add items: Tap products from the grid/list, or use search by name, or scan a barcode with a scanner or camera (if available).
  3. Quantity: For each line, set how many units the customer buys. The line total updates from quantity × price.
  4. Bundles: If you sell configured bundles, add the bundle like a normal product; the app checks stock for all parts inside the bundle before allowing checkout.
  5. Remove mistakes: Remove a line or set quantity to zero before payment.
If the app says out of stock, you cannot sell more than available quantity (for normal positive sales). Receive stock first (purchase / stock in) or fix the product stock after a physical count.

Prices, discount, and tax

  • The POS usually picks Retail Cash or Retail Credit / Wholesale price depending on payment type and wholesale mode — watch the totals when you switch modes.
  • Bill discount: If the screen has discount controls (percent or fixed), apply them before payment. Subtotal, tax, and total should match what you tell the customer.
  • Tax: Uses the tax rate from settings (unless overridden per line). Verify the final total on screen before taking money.

Selecting a customer (Khata / credit)

  1. Before or during the sale, choose a Customer from the customer picker if the sale goes on their account.
  2. For credit (Khata) sales, the app records what they owe. Some shops still take a partial payment on credit — enter the amounts the screen asks for.
  3. If your shop uses credit limits, the POS may block a sale when the new balance would exceed the limit.

Payment types and completing the sale

Typical options (your exact labels may vary):

TypeWhen to use it
CashCustomer pays full amount in cash. Enter tender if the app asks, so change can be shown.
CardFull or agreed amount paid by card / bank POS terminal.
SplitPart cash and part card (or other split). Enter both parts so they add up correctly.
Credit / KhataSale on account: customer pays later. Often requires a selected customer. Partial payment on Khata may be supported.
  1. Review the cart and total.
  2. Select the correct payment type and fill any amount fields.
  3. Tap Pay / Complete sale / Checkout (exact label varies).
  4. Wait for the success message. Stock and customer balance update automatically for a completed sale.
Some versions lock the Pay button after a successful sale until you start a new bill — this prevents double-charging the same cart by mistake.

After payment — new bill and printing

  1. Start a new sale / new bill when the next customer arrives (clear or reset the cart as your app shows).
  2. If you use a receipt printer, use Print or receipt preview from the POS or sale details screen.
  3. To review old bills, open Sales and tap a sale for line items and reprint if allowed.

Customers and customer ledger

Adding a customer

  1. Open Customers → Add Customer.
  2. Enter at least name and a phone number (phone helps you find them quickly).
  3. Set credit limit if you use limits.
  4. Save.

Ledger (Khata book)

Open Customer ledger (or similar) from the customer row to see running balance, past sales, and payments. Record payments there when the customer settles part or all of their debt.

Purchases, stock, returns, reports

  • Purchase orders / purchase invoice — record stock coming in from suppliers; this increases inventory without typing fake numbers on the product form.
  • Stock movements / inventory management — adjust stock when items break, spoil, or after a physical count, depending on what your app exposes.
  • Returns & refunds — process customer returns so stock and money stay accurate.
  • Suppliers & supplier ledger — track what you owe suppliers.
  • Banks / expenses — optional accounting-style tracking.
  • Reports — daily sales, item-wise sales, inventory, expenses — use these at closing time or for tax preparation.

Each sub-area has a dedicated HTML file in help_website/ (sales, supplier, bank guides) linked from index.html.

System backup (on your computer)

Backups are JSON files containing your shop data. They are created in your Documents folder under posbackup on typical Windows installs.

Manual backup

  1. Settings → Data Management → Create Backup.
  2. Confirm success. Open File Explorer → Documents → posbackup.
  3. Copy the newest manual_pos_backup_*.json file to USB or another PC.

Automatic backup (Windows)

  1. In the same section, enable Automatic Windows Backup.
  2. The app writes scheduled copies about every two hours while running, and may mirror to extra drives (D:, E:, etc.) when available.
Keep multiple recent backups. Disks fail; ransomware exists; one copy is never enough.

Online backup (free — no account)

  1. Settings → Data Management → Online backup (free).
  2. The app creates a fresh backup file, uploads it to a public host (transfer.sh or fallback 0x0.st), then shows a download link.
  3. Use Copy link and store the URL somewhere safe (email to yourself, password manager).
The link is sensitive (anyone with it may download your data). Free hosts may delete files after some time — always keep local backups too.

Restoring from a backup

  1. Copy the .json backup into Documents\posbackup if it is not already there.
  2. Settings → Restore Data → pick the file → confirm.
  3. Restoring replaces current data. Only restore when you intend to roll back.

Notes for the person selling this product

  • Walk through Add one product and one test sale on handover day while the buyer repeats the steps.
  • Explain stock: new shops often start at 0 and use purchases to increase stock — avoids inconsistent numbers.
  • Leave a printed shortlist: Dashboard → Categories → Products → POS → End-of-day backup.
